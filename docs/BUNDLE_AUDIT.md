# Engineering-Standards Bundle Audit

## Executive summary

This audit checks the World Cup Sweepstake app item-by-item against every applicable
engineering-standards bundle checklist: **146 requirements across 16 checklists**. Results:
**44 pass, 51 partial, 18 gap, 33 not-applicable**. There are **no critical or high-severity
findings**; the most severe items are 19 medium-severity partials/gaps, the rest are low.

The headline: the app is **substantially aligned** with the bundles once each requirement is
read against the app's real scale (12 friends, no user accounts, single locale, one shared
KV-backed draft, one rate-limited upstream). Its genuine strengths are chaos/degrade
resilience, upstream-budget coalescing, fail-closed auth, and secrets hygiene. What genuinely
remains is a short list of proportionate hardening: add a SAST gate in CI (public repo), put an
explicit deadline on the one outbound fetch, add a `Retry-After` header on 429s, publish a
two-journey SLO plus an uptime/error-boundary alert, add a `rel=canonical`, and complete the
ARIA tabs/table semantics. Most other partials are documentation formalisation (SLO doc,
severity rubric, postmortem template) rather than missing engineering.

## Update: fixes applied this session

The worth-doing-now items were addressed in code; the baseline stays green (validate, 124 tests, coverage above thresholds). Nothing committed.

Done:

- `Retry-After` on all 429 responses (draft plus both share routes).
- 5s `AbortSignal.timeout` on the football-data fetch, plus `maxDuration` on `/api/live` and `/api/cron/refresh`.
- `rel=canonical` and `og:url`; `robots.ts` blocks all crawling on non-production (`VERCEL_ENV`).
- New `/api/health` readiness probe (KV reachability plus cooloff), with tests.
- CodeQL SAST workflow (`.github/workflows/codeql.yml`); mark it a required check to make it merge-blocking.
- Accessibility: `tabIndex={-1}` on `<main>` so the skip link moves focus; login form `aria-invalid` / `aria-describedby` plus focus-on-error.
- CSP violation reporting and the read-coalescing regression test (prior session).
- Docs: `docs/slo.md`, `docs/incident-severity.md`, `docs/postmortems/TEMPLATE.md`, `CHANGELOG.md`, runbook ownership + rollback-first + an owned RTO/RPO table; the upstream tier reconciled to paid 20 req/min.

Deferred (documented; proportionate to a 12-friend app, or higher-risk right before kickoff):

- The full ARIA tabs pattern and `div`-to-`<table>` conversion (needs visual verification, risk of layout regression). The quick a11y wins were done.
- An explicit `SNAPSHOT_SCHEMA_VERSION` / `draft:state` version marker (touches the critical snapshot path; the field-presence guard works today).
- RNG dependency injection through the draft mutators (the draw's randomness is intentional; low value versus critical-path risk).
- The restore-drill run (needs production KV credentials; the runbook now lists it as a pre-tournament step).
- Uptime-probe alerting, CSP nonce, Testcontainers/k6 CI, OpenAPI/RFC7807, JSON-LD, SBOM, error-budget automation (infrastructure or over-engineering per this report's own recommendation).

## Not applicable (with reason)

These are correctly out of scope for a 12-friend, no-account, single-locale, KV-backed app:

- **Memory-hard password hashing / Authorization (IDOR) / Multi-tenancy isolation** — no user/password database and no per-user objects; one shared draft + snapshot behind a single organiser cookie.
- **SSRF / N+1 & unbounded fetch / Connection pools / Pagination** — only outbound call is a hardcoded upstream URL; fixed tiny dataset (48 teams, 12 players, ~104 matches); KV is stateless HTTP.
- **All SQL migration mechanics** — structural-vs-backfill split, batched backfills, online DDL/index builds, store/column moves, transactional migrations, DB constraints, migration testing — Vercel KV has no DDL, tables, indexes, or constraint engine.
- **Autoscaling policy** — Vercel platform-managed; upstream fan-out is bounded by the single-flight lock independent of instance count.
- **Distributed tracing / Metric cardinality budget** — single Next.js process with one upstream; nothing to trace across, no custom metric label surface.
- **Incident commander + status page** — no external stakeholders or SLA for a private group.
- **Feature-flag lifecycle / progressive rollout / flag cleanup / flag combinatorics** — no flag system; 12-user audience makes percentage canaries meaningless; Vercel instant rollback is the proportionate safe-rollout story.
- **Bounded contexts** — single small single-context domain with one ubiquitous vocabulary.
- **LLM feature evals** — the app calls no LLM at runtime.
- **All 7 i18n requirements** — single English locale; no translation pipeline, RTL, ICU plurals, or hreflang needed. Unicode is UTF-8 by default with no persisted free-text input.
- **Regulatory compliance (HIPAA/PCI/CCPA)** — no health, payment, or account/PII collection flows.

## Recommended actions

### Worth doing now (proportionate, high value for this app)

1. **Add a SAST gate to CI** (CodeQL or Semgrep, high-severity-blocking). The repo is public; this is the single highest-value security gap.
2. **Put a deadline on the one outbound fetch**: `AbortSignal.timeout(~5000)` on the football-data fetch, plus `maxDuration` on /api/live and /api/cron/refresh. Closes the only reliability medium and the capacity concurrency-cap medium at once.
3. **Add `Retry-After` to all 429 responses** (draft + share routes). One-line, satisfies two checklists.
4. **Run and record a pre-tournament restore drill** of `draft:locked:latest` into a scratch key with an integrity assertion. This is the irreplaceable state before a hard deadline.
5. **Add one uptime/synthetic probe** (home + /api/live) and a log alert on `[error-boundary]`, both pointing at the football-data runbook. Turns detection from user-reported into automated.
6. **Publish a two-journey docs/slo.md** (home render, /api/live: availability + p95) and reconcile the paid-vs-free football-data tier across code/docs.
7. **Add `alternates: { canonical: '/' }`** to root metadata, and gate robots/noindex on `VERCEL_ENV` so preview deploys are not indexable.
8. **Complete accessibility semantics**: finish (or downgrade) the ARIA tabs pattern, wrap standings/group tables in real `<table>` markup, add `tabIndex={-1}` to `<main>`, and add aria-invalid/aria-describedby + focus to the login error.
9. **Seed the draft-shuffle RNG** and add a global no-network guard + `sequence.shuffle` in the test setup so the draw is reproducible and tests are order-independent and offline-safe.
10. **Cheap docs**: a 3-tier severity rubric, an owner line + rollback-first note in the runbook, a postmortem TEMPLATE.md, a CHANGELOG, and an explicit SNAPSHOT_SCHEMA_VERSION in the snapshot.

### Over-engineering for this scale / defer

- Per-session random rotating/revocable tokens and a full RBAC matrix (one shared organiser).
- Full multi-window burn-rate error-budget machinery, RED/USE histograms, a /metrics endpoint, distributed tracing, and a dashboard-as-code stack (no metrics backend, 12 users).
- Multi-tier paging/on-call rotation, incident commander role, and a public status page.
- A feature-flag platform, percentage canaries, cohort ramps, and flag-combinatorial tracking.
- Formal hexagonal ports/adapters interfaces, dependency-cruiser boundary enforcement, and Testcontainers for every seam (current thin-accessor + in-memory fakes are defensible at this size; a single real-KV integration job is the one worthwhile upgrade).
- Hash-chained/signed tamper-evident audit log with a write-restricted KV role (a single prev-entry hash is enough if desired).
- OpenAPI + cross-team versioning/deprecation gates (in-repo typed consumer); RFC7807 problem+json is the only genuinely useful piece.
- JSON-LD structured data, C4 diagram tooling with CI rendering, EARS requirement/reverse-spec docs, and SBOM-per-release (nice-to-have, not load-bearing here).
